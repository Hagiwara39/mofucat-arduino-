# もふもふ猫 (Mofumofu Cat)

撫でると(触ると)猫のように「にゃー」と鳴く、猫型のタンジブル・インタラクション作品です。

> **🚧 制作途中のプロジェクトです。**
> 電子工作のコア部分(触れたら鳴る)は動作しています。筐体(猫の形)の設計・3Dプリント・外装はこれから取り組みます。内容は随時更新します

[![もふもふ猫プロトタイプ](https://youtube.com/shorts/y5mujTZHKJo?si=9VMgidgNuMvuZutu)

## コンセプト

触れる・撫でる・押す、といった身体的なインタラクションで反応するものを作りたい、という思いから始めたプロジェクトです。

- 単なる電子工作ではなく、**触れる → 反応する**という体験そのものを大切にする
- 完成度を最初から高めるのではなく、まず**コア体験が成立する最小のプロトタイプ**を作り、問題を見つけながら直していく
- 将来的には、ウェルビーイングや癒やしにつながるインタラクションへ発展させる可能性がある

当初は「もふもふの猫ボール」(球体)として構想していましたが、現在は**四足歩行で頭のある猫の形**にする方針に変更しています。

## 仕組み

```
撫でる/触る
  → 静電容量センサー(アルミホイル電極)が検知
  → Arduinoが「基準値より大きく変化したか」を判断
  → DFPlayer Miniに再生命令
  → microSD内の猫の鳴き声(0001.mp3)を再生
  → スピーカーから「にゃー」
```

「触れていない → 触れた」に変わった**瞬間だけ**鳴ります(手を置いたままでも連続再生しません)。連続再生を防ぐため、1.5秒のクールダウンがあります。

### 部品

| 部品 | 用途 |

- [DFRobotDFPlayerMini](https://github.com/DFRobot/DFRobotDFPlayerMini)

開発環境: Arduino IDE 2.3.10

## 配線

| 接続元 | 接続先 | 備考 |
|---|---|---|
| Arduino 5V | DFPlayer VCC | |
| Arduino GND | DFPlayer GND | **全部品でGNDを共通にする** |
| DFPlayer TX | Arduino D10 | SoftwareSerialの受信 |
| Arduino D11 | 抵抗 → DFPlayer RX | SoftwareSerialの送信。抵抗でノイズを低減 |
| DFPlayer SPK1 / SPK2 | スピーカーの2本 | どちらもGNDにつながない |
| Arduino D2 | 1MΩ → アルミホイル | センサー送信側 |
| アルミホイル | Arduino D4 | 受信側(ホイルは、抵抗とD4の接続点につなぐ) |

※ DFPlayer Miniは互換品によってピンの表記が異なることがあります。お手元の基板のシルク印刷で確認してください。

```
D2 ──[1MΩ]──┬── アルミホイル
             └── D4
```

## 使い方

1. 上の配線でつなぐ(ArduinoのIDEで`CapacitiveSensor`と`DFRobotDFPlayerMini`ライブラリをインストール)
2. microSD(FAT32)に、猫の鳴き声のmp3を **`0001.mp3`** という名前で保存し、DFPlayerに挿す
3. `cat_ball_touch_nyaa.ino` を書き込む
4. **ファー(外装)を重ねる場合は、重ねた状態で電源を入れる**
5. 電源を入れて**約5秒間は、ホイルに触らない**(その間に「触れていない状態の基準値」を測っています)
6. ホイルに触れると「にゃー」と鳴る

シリアルモニタ(9600 baud)では、`value`(センサー値)と`threshold`(しきい値)を確認できます。

### 調整

| 症状 | 対処 |
|---|---|
| 触っても鳴らない | `MARGIN`を小さくする(例: 100) |
| 触っていないのに鳴る | `MARGIN`を大きくする(例: 600) |
| 音が小さい | `volume()`を上げる(最大30)。mp3自体の音量も確認する |

## 制作中に分かったこと

これから作る人の参考になるよう、つまずいた点と切り分けの結果を残します。

### DFPlayerのノイズ(「ジジジジ」)

- 元のコードは`loop()`の中で再生命令を毎回送っており、曲が頭から再生し直されていました。再生命令は`setup()`で1回だけ、またはイベントごとに呼ぶ必要があります。`volume()`の範囲は0〜30です。
- 切り分けの結果は次のとおりです。

| 試したこと | 結果 |
|---|---|
| mp3をPCで再生 | ノイズなし → ファイルは原因ではない |
| 音量を下げる | ノイズだけ残った |
| USB給電をハブ→モバイルバッテリーに変更 | ノイズ継続 → PC側の電源ノイズではない |
| 再生中にD11の線を抜く | 再生は続き、**ノイズだけ消えた** |
| D11とDFPlayerのRXの間に抵抗を入れる | ノイズがほぼ消えた |

- ArduinoのTXは5V、DFPlayerのRXは3.3V系のため、直結するとノイズが乗りやすいことが知られています。**D11とRXの間に直列抵抗を入れる**のが有効でした。
- 0.2秒ほどの「ジッ」が残っています。VCC-GND間にコンデンサ(100〜470µF)を追加する案は、まだ試していません。

### DFPlayerの初期化が、たまに失敗する

- `begin()`が、ごくまれに失敗しました。接触不良や電源の揺れが疑われます。
- 最終コードでは、初期化を最大5回までやり直すようにしています。

### 静電容量センサー

- 触っていない状態の値は一桁、触れると数千〜2万台になり、検出には十分な差がありました。
- **ファー(タオル)を載せてから電源を入れる**と、厚い布越しでも手の接近を検出できました。起動時に「触れていない基準」を測るためです。先に起動してからファーを載せると、基準が崩れて検出できませんでした。
- 3つの改良を試した結果は次のとおりです。

| 改良 | 結果 |
|---|---|
| トラッキング(触れていない間、基準をゆっくり追従) | **最も効果あり** |
| ウォームアップ(起動直後の測定を捨てる) | 効果あり |
| デバウンス(3回連続で超えたら「触れた」) | 触っていないのに鳴るようになり悪化 → オフ |

- 「撫でる」動きの検出は、ホイルが動いてしまうため難しく、現在は「触れたら鳴る」のみです。

## 注意事項

- **鳴き声のmp3ファイルは、このリポジトリに含めていません。** 各自で用意し、`0001.mp3`として保存してください(利用許諾のある素材を使用してください)。
- 通電中の機器に、はんだ付けをしないでください。

## これからやること

制作の順序の目安です。進み具合によって変わります。

### 近いうち

1. **部品の実寸を測る**(Arduino、DFPlayer Mini、スピーカー、基板、ホイルなど)
2. **紙で猫の側面・上面のスケッチを描く**(部品の配置、配線の通り道、体を分割する位置)
3. **大学の3Dプリンターの造形最大サイズを確認する**
4. **Fusion(Autodesk Fusion)でモデリングを始める**
   - まず「空洞のある丸い箱」(スケッチ → 押し出し → フィレット → シェル)で操作に慣れる
   - 実寸をパラメータ化し、体を上下に分割して蓋のはめ合わせを作る
   - 頭・足を別パーツで作って付ける
5. **3Dプリンターで試し刷りし、部品が収まるか確認して修正を繰り返す**

### そのあと

6. ブレッドボードから**はんだ付けした基板へ移行**する(DFPlayerは使い回しのため、ピンソケット経由で接続)
7. **ファーやクッション層を重ねて、センサー感度(`MARGIN`)を最終調整**する
8. USBケーブルを、猫の**しっぽの位置**から出す形にまとめる(電池ボックス2本用は電圧不足のため不採用)
9. Fusionのデータ、配線図、写真・動画をこのリポジトリに追加する

### 余裕があれば

- 複数の「にゃー」をランダムに再生する
- 撫で続けると「ゴロゴロ」と鳴る / 振動モーターでゴロゴロ感を出す
- 撫で方・強さによる反応の変化(FSR=感圧センサー、加速度センサーとの併用)
- 持ち上げる、転がすといった動きへの反応
- 残る「ジッ」というノイズの除去
- 起動完了を、基板のLEDで知らせる(バッテリー運用時にシリアルモニタが見えないため)
- 小型化(Arduino Nanoなど)
